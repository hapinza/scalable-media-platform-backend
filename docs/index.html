STAGE 3 / BURST ACCEPTED AND BUFFERED

The burst was accepted, and every event was still accounted for.

The Redis-first path accepted 9,657 events while MySQL was stopped. HTTP success established acceptance; it did not establish downstream persistence, so I inspected the consumer group directly.

The 42 pending entries had been delivered to a consumer but were unacknowledged, because the database write behind them could not complete. The rest were still waiting in the stream.

Undelivered entries drained to zero.

Each successive inspection of the consumer group showed lag falling as the backlog was delivered and persisted. Every entry in the stream was eventually handed to a consumer.

Delivery is not completion. What the lag counter measured was how much had been handed over, not how much had finished.

STAGE 7 / ROOT CAUSE

My recovery lookup excluded the owner.

The scheduler queried pending entries scoped to recovery-consumer. The 97 entries still belonged to consumer-1, so the lookup returned 0. Redis had preserved every message correctly; my recovery worker could not see them.

STAGE 8 / FIX VERIFIED

Recovery could see the whole group's work.

I changed the scheduler to scan pending entries across the entire consumer group and use XCLAIM to reclaim stale ones. The recovery consumer became the claim target rather than the lookup scope.

Pending fell 97 → 37 → 0. All 9,657 accepted events were persisted.

Why both write paths exist

Transactional Outbox

The business update and its outbox event commit in the same MySQL transaction. The publisher then forwards the event to Redis Streams.

This path protects consistency between the database write and event publication. Accepting the write requires MySQL.

Redis-first ingestion

View events enter Redis Streams before downstream database persistence.

This path lets ingestion continue while MySQL is unavailable, provided Redis remains available. It is the path exercised in the outage timeline above.

Outbox consistency result

In a separate Outbox test, every committed event was recovered.
